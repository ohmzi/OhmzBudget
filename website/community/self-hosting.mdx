# Self-hosting with Docker

Besides the desktop app, you can run OhmzBudget on your own server (a home server, a NAS, or a small cloud machine) and open it from any browser, like Actual Budget or Firefly III. It runs in a single Docker container, and you sign in with your own account.

:::info

The desktop app doesn't need any of this. Self-hosting is for when you want to reach your budget from several devices, or share it with someone in your household — each person gets their own account.

:::

## Quick start

You need [Docker](https://docs.docker.com/get-docker/) with Docker Compose.

1. Create a folder for OhmzBudget and download the example [`docker-compose.yml`](https://github.com/ohmzi/OhmzBudget/blob/main/docker-compose.yml) into it.
2. Create the encryption key that protects your stored bank credentials, and make it readable only by OhmzBudget (which runs as user id 1000). If you're logged in as root, leave out `sudo`.

   ```bash
   openssl rand -base64 32 > ohmzbudget_data_key.txt
   sudo chown 1000:1000 ohmzbudget_data_key.txt
   sudo chmod 400 ohmzbudget_data_key.txt
   ```

   Keep a copy of the key somewhere safe (a password manager works well), separate from your backups. Without it, OhmzBudget can't read your saved bank connections, and you'd have to connect your banks again.

3. Start OhmzBudget:

   ```bash
   docker compose up -d
   ```

4. Open `http://<your-server>:3001` in a browser and **create your admin account**: pick a username and a password, then enter the **setup code**, which only appears in the server's log:

   ```bash
   docker logs ohmzbudget
   ```

   The code makes sure only someone with access to the server can create the first account, not whoever happens to open the page first. That account is the **admin**: it can add accounts for other people in **Settings → Server → Users**.

That's it. Your budget is stored in a Docker volume.

:::note[OhmzBudget won't start?]

Check `docker logs ohmzbudget`. If it can't read the key file, make sure `ohmzbudget_data_key.txt` belongs to user id 1000 (step 2). The key must be 32 random bytes in base64, which is exactly what the `openssl` command above creates.

:::

:::warning[Docker bypasses your firewall]

Docker opens published ports on every network interface, and firewalls like `ufw` don't block them. If OhmzBudget sits behind a reverse proxy on the same machine, publish it only locally by changing the port line in `docker-compose.yml` to `'127.0.0.1:3001:3001'`.

:::

### Without Compose

```bash
docker run -d --name ohmzbudget -p 3001:3001 \
  -v ohmzbudget-data:/data \
  --read-only --tmpfs /tmp --cap-drop ALL --security-opt no-new-privileges:true \
  -v "$PWD/ohmzbudget_data_key.txt:/run/secrets/ohmzbudget_data_key:ro" \
  -e OHMZBUDGET_DATA_KEY_FILE=/run/secrets/ohmzbudget_data_key \
  --restart unless-stopped \
  ghcr.io/ohmzi/ohmzbudget:latest
```

### Building the image yourself

```bash
git clone https://github.com/ohmzi/OhmzBudget.git
cd OhmzBudget
docker build -t ohmzbudget .
```

Then use `ohmzbudget` instead of `ghcr.io/ohmzi/ohmzbudget:latest`.

## Using it over the internet: HTTPS

On your home network, `http://` is fine. **Before making OhmzBudget reachable from the internet, put it behind a reverse proxy that provides HTTPS**, such as [Caddy](https://caddyserver.com/), Traefik, or nginx. Otherwise your password and budget travel unencrypted.

With Caddy, the whole configuration is (use `localhost:3001` instead of `ohmzbudget:3001` if Caddy isn't running in Docker on the same network):

```
budget.example.com {
    reverse_proxy ohmzbudget:3001
}
```

Then tell OhmzBudget about the proxy and your address in `docker-compose.yml`:

```yaml
environment:
  - OHMZBUDGET_TRUST_PROXY=1
  - OHMZBUDGET_ALLOWED_HOSTS=budget.example.com
```

`OHMZBUDGET_TRUST_PROXY=1` lets OhmzBudget see that the connection is HTTPS, so your login cookie is only ever sent over HTTPS.

## Settings

| Variable                          | What it does                                                                                                                                                                                                                                                                                                          |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OHMZBUDGET_DATA_KEY_FILE`        | Path to the file holding the encryption key (a Docker secret). **Required** (or `OHMZBUDGET_DATA_KEY`).                                                                                                                                                                                                               |
| `OHMZBUDGET_DATA_KEY`             | The key itself, instead of a file. Less private: anyone who can run `docker inspect` can see it.                                                                                                                                                                                                                      |
| `OHMZBUDGET_ALLOWED_HOSTS`        | Comma-separated addresses OhmzBudget answers to, e.g. `budget.example.com,192.168.1.20`. Recommended; by default it answers to any address.                                                                                                                                                                           |
| `OHMZBUDGET_TRUST_PROXY`          | Set to the number of reverse proxies in front of OhmzBudget (usually `1`) when using one.                                                                                                                                                                                                                             |
| `OHMZBUDGET_INTERNAL_FETCH_ALLOW` | Private hosts OhmzBudget may call (e.g. `paperless:8000`), comma-separated. Entries match the address's host exactly, so a host that listens on a non-default port must be written with it (`paperless:8000` matches; `paperless` alone doesn't). Not used yet: the document-import features that need it come later. |
| `PORT`                            | Port inside the container (default `3001`). You'll usually change the port mapping in `docker-compose.yml` instead.                                                                                                                                                                                                   |

## Your account

The first visit creates the **admin account**: a username, a password, and the one-time setup code from the server log. The password is stored as a scrypt hash, never in plain text.

- **Settings → Server → Users** lists the accounts. An admin adds more with **Add user**, each with a **member** or **admin** role; everyone shares the same budget and signs in with their own username and password.
- Change your own password in **Settings → Server**. That signs out your other devices, not anyone else's.
- An admin resetting someone's password signs that account out everywhere; after 10 wrong attempts, logins are blocked for up to 15 minutes.
- Forgot the admin password? Remove the saved password (this also signs everyone out):

  ```bash
  docker exec ohmzbudget node reset-password.cjs
  ```

  Then open OhmzBudget and create the admin account again, using the new setup code from `docker logs ohmzbudget`.

## Backups

Everything lives in one SQLite file, `budget.db`, in the `/data` volume. To make a backup while OhmzBudget is running:

```bash
docker exec ohmzbudget node backup.cjs
docker cp ohmzbudget:/data/backups ./ohmzbudget-backups
```

The first command saves a complete, consistent copy to `/data/backups` inside the volume; the second copies all your backups to the `ohmzbudget-backups` folder next to your `docker-compose.yml`. Don't copy `budget.db` directly while OhmzBudget is running: recent changes may still be in a separate `budget.db-wal` file.

To restore, stop OhmzBudget, put the backup in place as `budget.db` and start it again:

```bash
docker compose stop
docker run --rm --volumes-from ohmzbudget -v "$PWD/ohmzbudget-backups":/backups alpine \
  sh -c 'rm -f /data/budget.db-wal /data/budget.db-shm && cp /backups/<backup-file>.db /data/budget.db && chown 1000:1000 /data/budget.db'
docker compose start
```

You can also download a JSON backup of your data from **Settings → Data** at any time. Keep `ohmzbudget_data_key.txt` backed up too, separately from the database.

## Updating

```bash
docker compose pull
docker compose up -d
```

Database updates are applied automatically when the new version starts. Back up first, just in case.

## How the container is secured

- It runs as an unprivileged user, never as root.
- The example Compose file makes the container's filesystem read-only, drops all Linux capabilities, and blocks privilege escalation.
- Creating the first account (an admin) needs a one-time setup code from the server log, so nobody else can claim a freshly started server.
- Passwords are stored as scrypt hashes, never in plain text. Login sessions are random 256-bit tokens, stored only as hashes, in a cookie scripts can't read, and they expire after 30 days.
- Accounts have roles: only admins can manage accounts and API tokens. Machine callers (a sidecar, a webhook) use revocable API tokens instead of an account.
- Behind HTTPS, OhmzBudget tells browsers to always use HTTPS for your address (HSTS).
- Bank credentials (Plaid and SimpleFIN) are encrypted with your key, which is kept outside the database.
- Every image is built by GitHub Actions from the public source code, for both `amd64` and `arm64`, with a software bill of materials (SBOM) and a signed build attestation, and is scanned for known vulnerabilities every week. You can check an image really came from this repository:

  ```bash
  gh attestation verify oci://ghcr.io/ohmzi/ohmzbudget:latest -R ohmzi/OhmzBudget
  ```

See [Security](./security.mdx) for everything else OhmzBudget does to keep your data safe.
